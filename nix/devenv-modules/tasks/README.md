# Task Organization

This directory contains devenv task modules organized by reusability.

## `shared/` - Reusable Tasks

These tasks are meant to be imported by other repos via the flake input:

```nix
# In another repo's devenv.nix
imports = [
  (inputs.effect-utils.devenvModules.tasks.check {
    checkQuickTypecheckTask = "repo:typecheck";
  })
  (inputs.effect-utils.devenvModules.tasks.lint-oxc {
    lintPaths = [ "src" "test" ];
    geniePatterns = [ "*.genie.ts" ];
    genieCoverageDirs = [ "." ];
  })
  (inputs.effect-utils.devenvModules.tasks.flake-lock-duplicates {
    lockfiles = [ "flake.lock" ];
  })
];

tasks."repo:typecheck".exec = "pnpm exec tsc --noEmit";
```

`checkQuickTypecheckTask` must name a task defined by the consuming repository;
`checkAllTypecheckTask` defaults to the same task. The module retains
`ts:check` as its compatibility default, while Buck-owned repositories should
select their own aggregate explicitly (for example, `buck2:quick` and
`buck2:all`).

pnpm source-input staging resolves `repos/<member>/...` with genie's
bootstrap-safe member resolver. The initiating workspace's `megarepo.lock`
selects the member source, not the potentially newer tracking symlink.
Explicit `GENIE_MEMBER_OVERRIDE_MAP` overrides have the same precedence as
genie imports. Materialize pinned sources with
`mr apply --worktree-mode commit --lock-sync off` before staging.

`mr:lock-sync-check` matches named Nix lock inputs to their exact same-repository
megarepo members. An unnamed input is accepted when its revision matches any
member of that repository, including several members at the same revision.
If none match, it reports `no-declared-revision`.

The check module also exports `config.effectUtils.buck2.aggregateExec`, taking
a task name and a list of Buck2 arguments (including the subcommand). Existing
consumers of `tasks/shared/check.nix` need no additional import:

```nix
env.BUCK2_BIN = "${inputs.effect-utils.packages.${pkgs.stdenv.hostPlatform.system}.buck2}/bin/buck2";
env.OTEL_SPAN_BIN = "${inputs.effect-utils.packages.${pkgs.stdenv.hostPlatform.system}.otel-span}/bin/otel-span";
tasks."bird:build".exec = config.effectUtils.buck2.aggregateExec "bird:build" [
  "build"
  "//flakes/bird:dist-package"
  "//flakes/bird:bird-candidate"
];
```

The helper preserves task tracing, the caller-root command span, event logs/build
IDs, pipeline spooling versus standalone ingest/export, and the Buck2 exit status.
`effectUtils.buck2.eventsPackage` defaults to the consumer's effect-utils input;
`effectUtils.buck2.prepare` optionally supplies repository-specific setup before
the command (for example, effect-utils' capability publication).

## Holder-evidence protocol library (inactive)

`shared/worktree-holder-evidence-protocol.nix { inherit pkgs; }` builds only
the std-only Rust v1 protocol library and its synthetic codec fixture runner.
It does not enroll a client, inspect processes, install a service or authorize
worktree/store removal. Parsing is not evidence of authenticated or fresh absence.
The strict codec, seven-field store request parser and in-process SHA-256 are
extracted from reviewed snapshot `baffe1f018f69e2984a1ecf51de73a4d72dc93d1`.
SHA-256 retains its interruptible deadline and stack-only padding; it no longer
imports the Linux subprocess runner.

The Rust entrypoint is `shared/worktree-holder-evidence-protocol-lib.rs`, with
public modules `protocol`, `request` and `digest`. Compile it directly with
`rustc --edition=2024 --crate-name holder_evidence_protocol --crate-type rlib`;
`rustc --edition=2024 --test` on the same file selects the unit test runner.
The Nix build runs those tests, links `shared/worktree-holder-evidence-codec.rs`
against that library and always compares the executable's generated stdout
byte-for-byte with
`packages/@overeng/megarepo/src/store/fixtures/worktree-holder-evidence-v1.jsonl`.
The ten-case fixture is 12,745 bytes, SHA-256
`06e42489f5e4d1664146a4e169bed0cb0f9ac5e0cb1c360b7d2cc0991c0b5bb7`;
its first nine cases are unchanged. The additional synthetic in-use FD case
contains optional `leaderFdAlias` observation metadata, not exemption authority.
The independent library test asserts the byte length, digest, case count and
exact generated bytes. These fixtures are not live census qualification.

A worker FD may carry `leaderFdAlias` only when retained leader/task pidfds,
their exact generation identities, `kcmp(KCMP_FILES)` shared-table equality,
and `kcmp(KCMP_FILE)` equality for the same numeric slot all close successfully.
The metadata repeats and binds the containing TGID/leader start/TID/task start/FD
and the fixed proof tag `pidfd-kcmp-files-and-file-v1`. Errors or unsupported
checks do not produce an alias; loss during final closure aborts the frame.
It never removes a producer reference or permits a consumer to ignore a foreign
pin. Existing owned-pin authentication and object/lifetime checks remain required.
The ignored real worker test exercises table sharing, private-table inheritance
and reopening the same inode with another OFD; it requires isolated Linux
`CAP_SYS_PTRACE` and does not run as part of ordinary sandboxed unit tests.

## Native holder membership library (inactive)

`shared/worktree-holder-evidence-mounted.nix { inherit pkgs; allowedRoots = [ ]; }`
builds the native mounted-root and candidate-membership library after the pure
protocol and kernel libraries. It installs no server, client adapter or service.
An empty enrollment has no eligible candidates; production callers must supply
the same reviewed native enrollment as their server policy.

`NativeView` pins the task root, authenticated mount namespace FD, complete
bounded kernel mount snapshot and actual mountpoint objects. Native absence
never relies on `/proc/<tid>/mountinfo`, whose contents are filtered by chroot.
The read-only `listmount`/`statmount` queries select the pinned namespace FD;
`NS_GET_MNTNS_ID` must agree with every returned record. Independent
`NS_MNT_GET_INFO` cardinality must agree with the complete list before and after
the scan, so reachability-filtered partial lists cannot qualify. Final closure
rechecks the namespace identity, whole mount set and all retained record fields,
not merely IDs or a mount count. Unsupported APIs, denied access, a changed
view or an unverifiable physical mapping invalidate the observation: no fallback,
`setns`, namespace mutation or additional capability is permitted.
`CandidateSet` matches component-scoped physical source membership, including
mounted roots, not mere textual mount paths or common hardlinks. Store inode
inventory is deferred until after the caller authenticates its original exclusive
maintenance lease; worktrees are never recursively inventoried. Ordinary terminal
devices have no candidate path and do not become protective unknowns.

The builder runs pure codec and path tests against the reused lower libraries.
Real native filesystem fixtures run explicitly in the controlled NixOS VM,
not a build-sandbox chroot that cannot prove the complete host mount set.
The isolated bind/detached-mount controllers require `CAP_SYS_ADMIN`, but the
jailed-task regression queries through the production privilege profile without
that capability. Its outside-chroot candidate bind must appear in a complete
kernel listing that matches a privileged test-only oracle and must veto.
The exact child test must execute once; access refusal or an incomplete listing
fails qualification rather than passing as the expected veto. A skipped
privileged fixture, library success or codec success never authorizes deletion.

An internal memfd cannot be bind-mounted into a candidate on Linux 6.18.62:
`fs/namespace.c:2984-3018` rejects the internal, unattached source with EINVAL
(`fs/mount.h:131-134`). The controlled VM asserts this exact syscall errno and
preserved target/frozen scope. It does not pretend to cover a successful internal
memfd bind. Real detached tmpfs file/directory and candidate-submounted tmpfs
unlinked-file negatives remain distinct mandatory cases; no generic tmpfs
exclusion follows from the memfd refusal.

Owned-VM class diagnostics also label an already-selected proxy fallback with
only the closed reference kind, object category and exact overlay/FUSE class.
They reuse existing metadata and filesystem results: no new observations or
derived paths/identifiers, and no provider activation or qualification change.
A disabled managed provider still returns protective Unsupported.

## Privileged holder server (inactive)

`shared/worktree-holder-evidence-server.nix` accepts `pkgs`, `allowedRoots`,
non-root `ownerUid`, and optional `managedPolicy` (default `null`, fail closed).
It builds the actual privileged server and Rust unit runner, but installs no
socket/service, unprivileged client adapter, or consumer binding. Its executable
defaults to only `--serve-once`; every other mode or additional argument fails closed.
An inherited authenticated fixed-endpoint socket is required for a live request.

The server links the protocol/digest, proc, and mounted-membership libraries.
The mounted constructor receives the exact same `allowedRoots` as the server
policy digest. Ordinary process/task generations, credentials, namespaces,
resource pins, and closure rechecks belong to the proc library; root membership,
original collector EX-FLOCK authentication, mounted-source vetoes, and managed
runtime policy remain in the server assembly. The sole source-authenticated
bootstrap role still classifies its actual root/cwd/exe/stdio and mappings.
Capture failures remain protective UNKNOWN. Root-journal diagnostics identify
only a static capture/reclosure stage, `io::ErrorKind`, and numeric OS errno.
Native-scope failures additionally emit only their audited source-literal reason
through an `&'static str` helper, preserving the original `Other` kind and message.
Anonymous-object qualification uses a closed enum of exact kernel spellings.
BPF map/program/link, eventfd, timerfd, signalfd, epoll, inotify, pidfd,
userfaultfd and perf_event are typed non-path kernel objects in the agreed
accidental-breakage model; a bpffs pin is a separate filesystem path.
io_uring, fanotify and every unrecognized spelling remain protective UNKNOWN.
Rejected objects report only a fixed diagnostic class, never their proc-link target.
The isolated proc-test runner includes a real eventfd qualification and a real
io_uring with a registered candidate file (ordinary candidate FD closed) veto.
Diagnostics never format an underlying error object, foreign paths, process
identities or pseudo-file contents. Remaining rejections keep their original
error; the wire format and consumer authority rules are unchanged.
Controlled disposable VMs may explicitly set `ownedVmClassDiagnostics = true`
on the same-binary constructor. It defaults to false through every constructor,
has no runtime/environment switch, and produces distinctly named diagnostic artifacts.
The server's direct and mounted-library dependencies select the same proc variant,
so their transitive Rust crate identities remain coherent.
The exact bare `anon_inode:btf` BPF type-metadata descriptor is also a typed
non-path object; bracketed, prefixed and child-path variants remain unknown.
The ignored root-only `actual_loaded_btf_is_nonpath` regression loads a real
minimal BTF object with `BPF_BTF_LOAD` and qualifies its retained descriptor
inside the disposable Linux VM, without loading a BPF program.
The exact `bpf_link` and `bpf-link` constructor spellings share typed BpfLink.
The exact `bpf-stats` statistics-enable lease is independently typed non-path:
its private data is NULL, creation increments a global static key, and its sole
release callback decrements that key. The root-only ignored regression
`actual_bpf_stats_lease_is_nonpath` enables real runtime statistics with
`BPF_ENABLE_STATS`, qualifies the retained descriptor and closes it via RAII.
`bpf_iter` is **not** covered by a BPF-prefix exemption: target-specific seq
state can retain resources, including a DMA-buffer reference across reads,
so it remains UNKNOWN. Every unapproved or future name remains UNKNOWN.

Task departure is a separate, generation-pinned proof, not a missing-file waiver.
A nonleader is departed only when the original retained leader scope's task
relist no longer contains it, bracketed by same-generation checks and a live
original leader pidfd. An unreadable list, changed/terminal leader, reused
numeric task ID, or still-live task is not a successful departure proof.
Discovery and reclosure allow only such departures; newly live unobserved tasks
remain protective. Surviving tasks still require all UID/namespace/resource,
mounted-root and alias checks. Resource `None` slots retain their original
task index and must reprove departure at closure, never generic ENOENT.
Already recorded positive references can conservatively remain after departure.

Any remaining NotFound gets at most one **whole capture transaction** restart:
the failed attempt's observation and candidate/store/peer-root/census/mount/alias
pins are dropped, the original authenticated peer and server role revalidated,
then all state recaptured under the original deadline/nonce/expiry. There is no
partial rescan/publication, extended deadline, permission/Other/timeout retry,
or second restart; persistent failures serialize protective UNKNOWN.
The ignored real `actual_departed_thread_churn_preserves_survivor_fd` fixture
keeps a candidate FD in a surviving worker's private descriptor table while
listed siblings exit and further real threads churn between discovery and
resource closure. It requires that survivor FD to remain observed, rejects
uncaptured live newcomers and live-task FD disappearance, and rejects a failed
leader-generation proof. It does not claim arbitrary continuous live births
can always close within a finite observation deadline.
The fixture records each real TID and waits for actual task-list disappearance
under that same deadline before closure: pthread join's clear-child-TID wake
precedes kernel task removal and is not itself a departure proof. Listed IDs
are never discarded on timeout, and unrelated live newcomers remain vetoed.
The explicit diagnostic proc variant also emits finite static resource-stage
labels with only error kind and numeric errno at failing capture/recheck
boundaries, returning the original Result unchanged. Normal builds compile
that output out. A diagnostic VM must separately opt in and assert the
`ownedVmClassDiagnostics` passthru on its actual proc-tests runner; enabling
only the serving library does not instrument a separately imported test binary.

`map_files` has a distinct procfs interface: Linux6.18.62
`fs/proc/base.c:3297-3300` exposes it on top-level `/proc/<actual-tid>`,
but the complete nested `/proc/<tgid>/task/<tid>` table at3647-3745 does not.
Top-level lookup3489-3517 resolves that actual TID, including nonleaders;
it does not substitute the leader's address space.
Each TaskScope therefore retains a separate same-TID `mapping_scope`, pinned
inside the original generation/UID/namespace discovery bracket and compared
with fresh exact top-level scope identity during reclosure/recapture. The
original nested scope is separately rechecked and still supplies actual-task
FDs, root/cwd/exe and the authenticated mount namespace FD. Every ordinary and management
`map_files` enumeration, member pin and final recheck uses the mapping scope.
Missing/replaced scopes retain departure-proof/retry/UNKNOWN behavior, never
an empty-map fallback or a shared/leader-mm assumption. The real churn fixture
asserts nested map_files is absent, top-level same-TID mappings are nonempty,
and an actual retained read-only private candidate-file mmap is observed
alongside the surviving FD through production capture and reclosure.

The same default-false owned-VM flag also enables the actual mounted-membership
RLIB and its test compilation. Membership failures emit only finite static
boundary labels, error kind and numeric errno; native-location proof failures
add a finite source-literal rejection tag while returning their original error.
An unsupported-filesystem diagnostic distinguishes only the already-read exact
9p magic from a fixed `other` class. It grants neither filesystem support nor a
fallback. No path, mount/process identity or underlying error is formatted, and
ordinary builds compile all these diagnostic emissions out.
On that same failing native-location result only, owned-VM diagnostics also
classify the already-read metadata as file/directory/other, linked/unlinked, one
of the six supported native filesystem classes (or fixed other), and the closed
ReferenceKind. These are same-object snapshot tags, not retained-byte absence,
memfd identity or detached-mount reachability proofs; they never change UNKNOWN.

Unlinked tmpfs is not a blanket exemption. Only FD/MAP regular files with zero
links, exact tmpfs magic and the exact device **and mount ID** of a fresh live
transaction memfd witness can be non-holding, and only when that device is absent
from the complete verified candidate/scope device inventory. Exact historical
store inode positives still run first. Ordinary detached tmpfs, directories,
root/cwd/mount references and missing/changed proofs retain their veto.

That inventory includes physical-source aliases in both component-prefix
directions, every mount at/beneath each potential alias, file binds and covering
ancestor mounts. Hidden candidates may conservatively add devices, never lose
them. The enrolled view and every contributing task view retain complete mount
snapshots and verified mountpoint pins. The cache moves into each observation's
MountCoverage. Before full object reclosure, a ledger requires all contributions
retained and the cache empty, then freezes the union. Every earlier reference,
including provisional empty matches, is recomputed with its original retained
view and that complete frozen union; no later view registration is admitted.
Enrollment, all scope snapshots/pins and the witness reclose before publication.
New/changed/unresolvable submounts yield UNKNOWN, not an incomplete device set.
The fixed memfd syscall creates an empty CLOEXEC/no-exec-sealed non-hugetlb file,
retained only for this transaction and recreated on its sole whole-scan retry.

`HOLDER_EVIDENCE_PRODUCER_ID` is the final executable package's output placeholder,
not any linked library's identity. Peer executable authentication remains bound
to that same output's `bin/worktree-holder-evidence`. A later combined client
package must compile both roles in that final package environment; this
server-only artifact does not authenticate an independently packaged client.
The package exports neither `holderEvidenceClient` nor `processEvidenceCommand`.

## Same-binary holder clients (inactive)

`shared/worktree-holder-evidence.nix` uses the same policy parameters and compiles
the server and its strict clients into one immutable executable. The standalone
server constructor remains server-only by default; the client constructor enables
the client source at compile time, not through an environment or runtime override.
No socket, service, scheduled cleanup or deletion is installed by either package.

`--client-v1` accepts strict worktree JSON and returns validated fresh v1 evidence.
`--pnpm-client-v1 --pnpm-store-evidence-v1 ...` preserves the fixed seven-field
store contract. Both authenticate the fixed root-owned socket, same-host boot,
actual root peer, complete requested scope and suspend-inclusive proof expiry.
The server independently authenticates the real parent collector and its original
root/exclusive-maintenance-lease open-file descriptions for store observations.
The client creates no artificial cwd reference to the candidate.

The final package exports `holderEvidenceClient = { path; producerId; policyId; }`
and `processEvidenceCommand`, a fixed wrapper for that **same executable**. Its
producer ID is the final output directory, not a separately compiled client or
library. Generic worktree callers must veto every current reference, including
retained-byte records; only the immutable-store adapter may accept complete
byte-only evidence, and existing native store positives remain vetoes.

Every build reuses the protocol library's unconditional actual-codec fixture
comparison, then compiles/runs the real server/client unit runner. Deployment
additionally requires the single final integrated security review, actual root
service and confined-caller/whole-host qualification, and governed policy rollout.

## Observability

Aggregate tasks replace (never prepend to) `PATH` with nixpkgs Watchman's bin
directory by default. To use a signed host Watchman on macOS, explicitly declare
the executable in the ignored `devenv.local.nix`:

```nix
{
  effectUtils.buck2.watchmanBin = "/usr/local/bin/watchman";
}
```

The override must be absolute. A task-local `watchman` launcher executes that
exact binary without copying or modifying it. Buck2's Watchman client discovers
the CLI as `watchman` through `PATH`; it does not support a
`BUCK2_WATCHMAN_BIN`/`WATCHMAN_BINARY` selector. There is no ambient PATH probing.
Restart an existing Buck2 daemon (`buck2 kill`) after changing the selection;
an already-running Watchman server retains its original executable/permissions.

The pinned Buck entrypoint keeps Watchman socket, state, PID and log files in
`/tmp/eu-wm-<uid>-<home-hash>`, a current-user-owned 0700 directory. The hash is
the first 12 SHA-256 hex characters of the resolved HOME. The socket is `sock`
inside that directory (at most 39 bytes for a 32-bit UID), independent of HOME
depth. One HOME reuses one persistent service across commands/worktrees; different
job HOMEs remain isolated so one runner job's process cleanup cannot stop another
job's service. No per-invocation directories are allocated or services stopped.
The launcher exports `WATCHMAN_SOCK` for native Buck and passes the same socket
explicitly to admission's Watchman CLI, along with the managed state/PID/log paths.
An explicit `WATCHMAN_SOCK` remains caller-owned: hosts with their own managed
Watchman service may set it to that service's socket. Admission connects without
spawning or managing the host service. Oversized sockets or unsafe managed
directories fail closed with an actionable socket admission error; there is no
fallback to Watchman's potentially oversized HOME-derived path.

A niced gate may connect to a running managed service, but never spawn one.
Leftover `sock` or `pid` files do not establish that the service is running.
If the managed service has died, run the exact managed start command printed by
the priority admission error once **outside the gate, un-niced**, then rerun the
gate. That command selects the same socket/state/PID/log paths; Watchman acquires
its pidfile lock and replaces the stale socket itself. Do not manually delete
the socket or PID file or relax the shared service priority limit.

Standalone Watchman CLI queries and watch cleanup must also pass `--sockname`;
the CLI does not honor `WATCHMAN_SOCK` as native Buck does. The consumer-root and
file-watcher contract fixtures resolve the production location through
`prepareWatchmanEnvironment` and select it explicitly, including during cleanup.

Import the sibling observability module once to capture native devenv spans
and effect-utils task spans as one otelite trace:

```nix
imports = [
  (inputs.effect-utils.devenvModules.observability {
    project = "my-repo";
    # Optional: compose the full Collector/Tempo/Grafana stack.
    backend = "auto";
    # Optional: gate an existing aggregate task on the hermetic shape check.
    wireInto = [ "check:all" ];
  })
];
```

The default `backend = "ambient"` adds only `otel-span`, otelite, and the
`otel:profile:setup` / `otel:verify:setup` tasks. Task wrappers resolve the
module-owned bridge through `OTEL_SPAN_BIN`, so nested devenv task environments
do not depend on ambient `PATH`; capture tasks also prefer otelite's
invocation-scoped HTTP endpoint over a repository's ambient collector endpoint.
The module intentionally avoids the full local observability stack. Override
`profile` to capture a different task graph, or set `profile = null` when only
the packages and project attribution are needed. Use `profile.prerequisiteTasks`
for outer tasks that must complete before the nested devenv process can evaluate.

- `pnpm.nix` - pnpm install tasks
  - `lockfileMode = "frozen-in-ci";` allows local lockfile edits while passing
    `--frozen-lockfile` whenever `CI` is non-empty at runtime (including `CI=0`).
    With `CI` unset or empty it passes `--no-frozen-lockfile`.
    `"frozen"` always freezes installs; `"unfrozen"` never freezes installs.
    The legacy `frozenInCi` option defaults to `true` and, despite its name,
    maps to `"frozen"` everywhere; `false` maps to `"unfrozen"` everywhere.
    Omit `frozenInCi` when setting a non-null `lockfileMode`; combining them
    is an evaluation error. Update/dedupe remain explicit lockfile-authoring
    tasks, independent of the install lockfile mode.

    roots of the same OS user. `GITHUB_ACTIONS=true` or the explicit opt-in
    `PNPM_JOB_LOCAL_STORE=1` selects the job-local Store Cache under
    `<root>/.devenv/pnpm-store-pure-v1` (with a workspace suffix for nested roots).
    `CI=1` alone keeps shared storage, so non-watch dev-host tasks reuse the cache.
  - By default dependency graphs and `node_modules/.pnpm` remain
    Materialization-Root-owned. Pass `globalVirtualStore = true;` to opt local
    development into pnpm's graph-hashed shared projections with the isolated
    linker. Genie authors `enableGlobalVirtualStore: true` in workspace YAML.
    Hoisted linking does not use GVS.
  - GVS uses `PNPM_CONFIG_ENABLE_GLOBAL_VIRTUAL_STORE=true`, not the ineffective
    pnpm 12 kebab-case `--config` spelling, and leaves `virtual-store-dir` unset.
    Both modes use the complete shared store declared by
    `pnpm-install-contract.json` (`~/.local/share/pnpm/store-shared-v1`).
    `PNPM_SHARED_STORE_DIR` overrides the local shared store in either mode.
  - Job-local mode explicitly disables GVS (including inherited environment/YAML
    opt-ins) and uses the job-local store and projection. Other CI runners must
    set `PNPM_JOB_LOCAL_STORE=1` to obtain that isolation. Fixed-output preparation
    stays root-local and GVS-disabled.
  - Effective `frozenStore: true` policy also disables GVS, but retains the shared
    CAS selected above. The selector reads `pnpm config get frozen-store` using
    one absolute native binary resolved by the CLI guard's shared dispatcher:
    explicit `pnpmPkg`, otherwise the first non-guard pnpm on PATH.
    That path is selected once per storage prologue and used for policy reads,
    installation, and stale-projection repair, with the caller's isolated
    `XDG_CONFIG_HOME`. Shell entry needs no task guard passthrough.
    Both storage selection and stale-projection repair include configuration
    overrides from `installFlags` in that query. An explicit writable override
    (`--frozen-store=false` or `--no-frozen-store`) therefore retains GVS even
    under globally frozen policy.
    Builds run in writable `node_modules/.pnpm`, not the read-only shared
    `links/` graph. This overrides workspace GVS without relaxing offline,
    frozen-lockfile, or frozen-store policy. Only these read-only installs lose
    cross-root graph reuse; normal writable installs still use GVS.
    Stale projections are still purged, but rematerialization omits `--force`,
    which pnpm rejects with a frozen store.
  - Install, update, dedupe, status, doctor, and shell setup share the selected
    policy. Readiness receipts include effective GVS/store policy. Health and
    projection fingerprints visit only this root's reachable shared instances,
    not unrelated graphs. Repair removes only root-owned links, never shared
    graph instances. Stores are writable state for trusted same-user consumers;
    verify tools that depend on package realpaths or implicit dependencies
    before opting in.
  - Managed installs use pnpm's `auto` import policy and reject cross-device
    Linux storage before materialization.
  - `pnpm:store:migrate-legacy` explicitly replaces only the recognized
    historical `v11/files` bridge under the exclusive cache lease; normal
    installs and unknown bridges fail closed.
  - `PNPM_RETIRE_STORE_DIR=/path/to/legacy-store devenv tasks run pnpm:store:retire`
    reports a legacy host store's eligibility and unique-file byte size without
    deleting it. Set `PNPM_RETIRE_APPLY=1` to explicitly apply; the packaged CLI
    also accepts `pnpm-store-retire /path/to/legacy-store --apply`.
    The contract default and configured shared store are protected. Retirement
    enumerates current-repository git worktrees and, when `mr` is available,
    every worktree registered by repositories in `mr store ls --output json`.
    Root and nested workspace `node_modules` symlinks and CAS hardlinks refuse
    retirement, as do unidentified external hardlinks or incomplete proofs.
    The exclusive existing cache lease covers proof and deletion; apply renames
    to a sibling tombstone before deleting, leaving interrupted work retired.
    See [the host retirement contract](../../../context/dependency-materialization/04-store-authority/spec.md#legacy-host-store-retirement)
    for enumeration boundaries and failure behavior.
  - `pnpm-store-gc --git-dir /path/to/repo/.bare --root /path/to/worktree`
    reports historical root-local store retirement in a read-only dry-run.
    The collector supports Linux x86/x86_64 and ARM/aarch64, selecting each
    architecture's directory and no-follow open flags. Other Linux architectures
    fail at compile time rather than assuming compatible flags.
    On other platforms it exits nonzero before
    filesystem input access with `pnpm-store-gc: unsupported platform (Linux only; Darwin census not implemented)`.
    Repeat `--root` for explicitly selected worktrees; there is no fleet traversal.
    It never targets `$HOME/.local/share/pnpm` or `PNPM_SHARED_STORE_DIR`.
    Before ownership admission or lease creation, resolved paths and inode
    identities reject candidates overlapping either default shared store or
    `PNPM_SHARED_STORE_DIR`. Mount inventory also rejects mount points at the
    candidate root or below it, including same-filesystem bind mounts.
    Directory mount IDs define traversal containment; `st_dev` remains part of
    inode accounting only. Overlayfs payloads can expose differing backing
    device IDs without crossing a mount, so device-number inequality is not
    grounds to reject an otherwise contained historical cache.
    `--observe` records eligible roots without deleting payloads; after 24 hours,
    repeat the dry-run, then opt in to `--apply` to retire eligible payloads.
    An initial `--apply` only establishes the observation, never skips grace.
  - Eligibility requires the root to be absent from Git's worktree registry
    **and** have no `.git` marker, or its own checkout to have stopped owning
    the historical store. For effect-utils this is proved by HEAD containing
    `727cb7544bea32ec031c9f6e5e840cbe717e772a` (#1794). Consumer checkouts can
    prove resolved selection through matching `pnpm-storage-state` receipts
    and `.modules.yaml` metadata naming the default shared store (or the
    operator's `PNPM_SHARED_STORE_DIR`). Any projection still naming a
    worktree-local store protects the cache. Unknown metadata, incomplete
    ownership evidence, and Git worktree locks fail closed; PR closure alone
    does not prove a checkout stopped referencing its store.
  - The collector requires no own-UID cwd/open-fd references under the
    historical **store**, not the entire checkout, using Linux `/proc`.
    Other-UID processes are outside the normal
    user-owned-cache flow; the CLI states this assumption explicitly. Unreadable
    own-UID processes fail closed, except the explicit Linux privileged-broker
    allowlist. SSH brokers (`sshd-session`, Tailscale SSH's
    `.tailscaled-wrapped` executable or truncated `.tailscaled-wra` comm)
    require a root-owned fd directory. The `systemd` user-manager exception
    requires `PPid=1` and nonzero permitted capabilities. Its `(sd-pam)` child
    shares the same exception only when its PPid identifies that same approved,
    same-UID manager. Only `ESRCH` or disappearance of the PID directory proves
    a process gone. A live PID with missing leader cwd/fd evidence requires
    inventory of its remaining tasks; unreadable task evidence fails closed.
    Other unreadable process classes fail closed. Every exception prints the PID,
    comm, executable
    (or its read error), parent, permitted capabilities, and the normal-flow
    assumption that privileged brokers do not use pnpm stores. The invoking UID
    must own the store; no privileged observer or GitHub/API access is needed.
    It rechecks checkout ownership, process references, and every payload inode's
    size/link-count/mtime/ctime under a proved exclusive Store Cache lease before
    retirement. Changed observed eligibility resets the 24-hour grace.
    The candidate is opened once at admission: its directory descriptor and
    inode/mount identity remain held through lease acquisition, proofs, and
    retirement. The lease is opened relative to that descriptor, and its locked
    open-file description remains held in the same collector process. Pathname
    replacement aborts rather than admitting a replacement directory; deletion
    never reopens the root path and verifies its identity again at the end.
    Linux retirement walks held directory descriptors with `O_NOFOLLOW` and
    compares each opened directory's mount ID before descending or unlinking;
    a newly inserted mount or replacement symlink cannot redirect the walk.
    Observations live in `$XDG_STATE_HOME/effect-utils/pnpm-store-gc` (default
    `$HOME/.local/state/...`); the stable store directory and maintenance-lock
    inode remain, so cooperating pnpm mutations cannot bypass the lease.
  - Output lists `would-free`, `grace`, `protected`, or `absent` per root and a
    `would-free-total` in bytes. Reclaim estimates count allocated blocks once
    per inode and exclude payload inodes still hardlinked outside the selected
    store; `allocated=` also reports the gross store footprint. These are not
    physical reclaim guarantees on compressed, snapshotted, or clone-sharing
    filesystems. Unmanaged processes can start after a census: stop/unpin root
    users first; process evidence does not replace lifecycle ownership.
  - Historical attribution: `8c5bc8e6be49440f03b9b0bb9504264352d47bd8`
    (#692) introduced the `pure-v1` namespace for lifecycle-free, integrity-
    checked frozen installs, not because Buck/Nix required worktree-local CAS.
    `4514099e0` (#922) selected a complete shared Store Cache with root-owned
    topology. `727cb7544bea32ec031c9f6e5e840cbe717e772a` (#1794) stopped
    treating ambient `CI=1` as job isolation; ordinary dev-host tasks now share
    the cache even in non-watch CI mode. Copies created before that selection
    change can be historical, but age alone does not authorize their retirement.
  - Frozen installs and `pnpm:update` both use the current guarded pnpm
    runtime: pnpm 12 is outside the 11.5.2-11.14.0 `hasBin` window that
    required a separate lock mutator, so the dedicated pin is retired while
    `pnpmLockMutatorPkg` remains available for a future divergence. Root
    updates generate projections with validation deferred, repair the lock,
    then require `genie --check`; retained package records are rejected
    transactionally if they lose `hasBin` metadata.

- `devenv-module-tests.nix` - CI task that runs shell tests for reusable task modules

### Module shell-test scheduling

`devenv-modules:test` discovers every `shared/tests/*.test.sh` and requires each
script to appear exactly once in `genie/ci-workflow/test-platforms.json`'s
`moduleScripts` classification. The Nix import and shell dispatcher both reject
missing, stale, duplicate or overlapping entries before dispatch. Darwin runs
only Darwin-sensitive scripts; Linux and an unset platform run the complete
catalog, except entries marked `fullProfileOnly: true` are excluded when
`EFFECT_UTILS_CI_TEST=1`. In particular, `notion-integration-ci.test.sh` needs
the full profile's Notion task definitions: full-profile `check:quick` and
`check:all` run it through `test:notion-integration:ci-skip`, independently of
the platform-selected module-test aggregate.
The unit graph guard checks direct `devenv tasks run` lines in unit-selected
scripts, including literal shell-array task arguments, against evaluated task
names before executing tests. This cheap scan is not a general shell parser;
embedded fixture/stub strings and dynamically computed task names are outside
its scope. Platform/profile classification is independent of parallel-safety
admission.
`local/devenv-module-tests.sh` runs selected unaudited and shared-checkout state
scripts serially before starting a bounded worker pool for explicitly admitted
scripts. Only admitted scripts are ordered longest-first, with lexical
ties and weight one for scripts without a declared duration. Both phases keep
running after failures. The aggregate fails if any script fails, and stderr
records each script's UTC start/end timestamp, scheduling class, and original
exit status. Stdout and stderr are not discarded. The Nix task pins Bash,
GNU date, jq, and xargs; the runner uses the GNU/BSD common
`xargs -0 -n 1 -P <workers>` interface rather than Bash-version-specific `wait -n`.
Worker failures, including exit 255, are normalized only at the xargs boundary
so xargs cannot stop dispatching the remaining scripts. The supervisor waits
for the complete pool on ordinary failures and on INT/TERM to the supervisor.

#### Isolation admission audit

The parallel admission list is fail-closed: a newly platform-classified script
runs serially until its side effects have been reviewed. The audit at
[`1f4b2947`](https://github.com/overengineeringstudio/effect-utils/commit/1f4b2947b8cfe2617e34ade8e5fafb63fd2c5587)
admitted 42 of the original 43 scripts. Every admitted script runs in a
separate Bash process, preserving cwd/environment isolation. Their ownership
boundaries are:

- **Read-only checkout policy/inventory:** `buck2-no-python-actions`,
  `buck2-stage0-source-inputs`, `devenv-eval-source-roots`,
  `devenv-task-env-boundary`, `nix-cli-no-hash-refresh`, and
  `observability-capture`. Negative controls, when present, write only mktemp
  fixtures; none starts a checkout-owned Buck daemon.
- **Nix evaluation/copied sources:** `buck2-capability-source`,
  `buck2-rules-source`, `check-module-options`, `setup-module-options`, and
  `workflow-report-module-source`. Source mutations affect copies under
  mktemp, not the checkout. Store realization uses `--no-link`; concurrent Nix
  store access remains Nix-daemon-owned, with no store GC or checkout result link.
- **Private state/fixtures:** `buck2-rust-deps`, `changeset-check-bodies`,
  `devenv-eval-input-budget`, `megarepo-lock-sync`, `megarepo-status`,
  `pnpm-source-input-staging`, and `setup-cache`. Generated graphs, fake Cargo
  homes, SQLite databases, manifests, caches, and source staging all live below
  each script's mktemp root.
- **pnpm behavior:** `pnpm-gvs`, `pnpm-nested-roots-and-source-inputs`,
  `pnpm-shared-store-reuse`, `pnpm-source-input-refresh.integration`,
  `pnpm-task-smoke`, `pnpm`, and `test-task-smoke`. Stores and projections are
  fixture-local, including the deliberately shared/concurrent pnpm store:
  "shared" means shared between that script's fixtures, not between scripts.
  Smoke installs use private homes and fake providers; no repository install
  or repository node_modules mutation is scheduled.
- **Genie:** `genie-compiled-staging` and `genie-module-options`. Compiled output,
  generated JSON, task receipts, and scratch Git repositories are private.
  The compiled fixture reads repository node_modules through a symlink but
  writes its compilation/import staging into mktemp.
- **Lint/plugin fixtures:** `lint-no-tailwind`, `lint-oxc-file-list`,
  `oxlint-plugin-injection`, and `oxlint-rule-policy`. Repository policies and
  immutable plugin products are read; malformed inputs, generated task code,
  argument captures, and plugin overrides are private fixture files.
- **Trace adapters:** `otel-instr-gating`, `otel-run`, and
  `otel-scrape-oxfmt-wrap`. Adapters/providers are fixture stubs; capture files,
  homes, spools, and summaries are private, not the live observability backend.
- **Lock checking:** `flake-lock-duplicates` builds a no-output-link task wrapper
  and checks lockfiles inside its private workspace.
- **Pipeline/report/provider fixtures:** `pipeline-run`,
  `workflow-report-task-e2e`, and `deploy-task-e2e`. Git state, OTLP spools,
  GitHub outputs, summaries, and provider logs are private. The deploy fixture
  binds its local API to port 0 and stops its owned API process; it does not
  claim a fixed port or call a live deploy provider.
- **SecretSpec:** `secretspec-native-tasks` realizes a no-output-link stub
  package environment and uses a private home/repository/capture per fixture;
  it does not call a real provider or fetch secrets.

The three native lifecycle fixtures are also admitted. Starting daemons is not
itself shared-state access; ownership of their mutations is what matters:

- `buck2-capability-daemon.test.sh` owns a private HOME, temporary Buck roots,
  explicit isolation names, and a short private Watchman socket. Every Buck
  startup, migration stop, and cleanup names that private HOME/root/isolation.
  Every Watchman operation names its private socket; startup, state, config,
  log, PID file, and native shutdown are fixture-owned.
- `buck2-capability-publish.test.sh` owns its publication roots, lock files,
  synthetic Buck state, and HOME. The five competing publishers and crash
  victim all use those roots; signals/cleanup address only captured fixture
  PIDs. Failure diagnostics read native process metadata without mutating
  other processes. Retention writes/prunes only `capability-publisher.*`
  evidence directories, not any other suite script's fixtures or evidence.
  Nix GC-root queries/registrations name that fixture's own absolute root links.
- `worktree-teardown.test.sh` has a unique canonical mktemp parent for all Git
  worktrees, editor publications, and nested-checkout/collision probes. Although
  Buck state is under the caller's `$HOME/.buck/buckd`, its keys include those
  unique absolute checkout paths. The production teardown kills only the
  selected root's direct isolations and deletes only their shallow files/root
  leaf, never a shared ancestor directory. Cache entries use fixture-specific
  root hashes below its private `XDG_CACHE_HOME`. Watchman startup/shutdown uses
  the fixture's private socket; production release performs only `watch-del`
  for the selected fixture root, even if its no-spawn client reaches an ambient
  service in the fixture's no-Watchman branch. No whole-service/global watch
  deletion is issued.

The remaining original serial script is `devenv-task-graph.test.sh`: it invokes

`devenv-module-tests-runner.test.sh` is also serial. Its FIFO-gated fixtures

## Task Output

devenv renders a task's **stderr** by default. Its **stdout** is rendered only
when the run opts in — `showOutput = true` on the task, `--show-output`, or
`--verbose`.

That is about what devenv prints to a console, not about what escapes the
process. **Both streams reach a GitHub runner.** Measured on `ubuntu-latest`
with devenv 2.1.2: a `::warning::` emitted from a task became an annotation from
stdout with no opt-in, from stdout with `showOutput = true`, and from stderr —
all three indistinguishable from one emitted by the step itself. So workflow
commands work from either stream, and log grouping does too.

One caveat worth knowing when debugging locally: devenv selects quiet verbosity
when it detects `CLAUDECODE` / `OPENCODE_CLIENT` / `AI_AGENT`, and up to 2.2.x
that also suppressed `showOutput`
([cachix/devenv#3038](https://github.com/cachix/devenv/issues/3038)), so a
task's stdout could look missing inside a coding agent while being perfectly
visible in CI. Fixed upstream in 2.3: explicit `showOutput = true` /
`--show-output` now streams even at quiet verbosity. On older CLIs, use
`DEVENV_NO_AI_AGENT=1` or `--verbose` when measuring.

## Adding New Tasks

### For Shared Tasks:

1. Create file in `shared/<name>.nix`
2. Make it a function that accepts configuration parameters
3. Document usage in this README
4. Export in `flake.nix` under `devenvModules.tasks.<name>`
5. Keep it generic - no hardcoded paths

### For Local Tasks:

1. Create file in `local/<name>.nix`
2. Define tasks directly (no parameterization needed)
3. Import directly in `devenv.nix` via relative path:
   ```nix
   imports = [ ./nix/devenv-modules/tasks/local/my-task.nix ];
   ```
4. Do NOT export in flake.nix
