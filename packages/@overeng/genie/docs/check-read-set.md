# Genie Check Read-Set Specification

This document specifies optional check read-set evidence for `@overeng/genie`. It builds on [requirements.md](./requirements.md), especially **R02** (strict drift detection) and **R03** (deterministic output), and extends the check pipeline in [spec.md](./spec.md).

## Status

Draft

## Scope

The optional interface is `genie --check --read-set FILE`: one recording, a versioned artifact, producer and consumer validation, and an actionable per-repo incompleteness report. It covers discovery, resolution/import/execution, stringify/format, target comparison, and every validator. It MUST NOT change generated bytes, validation policy, ordering, or check results.

Containment, sandboxing, subprocess confinement, and generator restructuring are outside this contract. Any such extension requires a separate design informed by the incompleteness report. Existing uncontained capabilities MUST remain visible as incomplete; recording MUST NOT manufacture completeness to obtain reuse.

## One recording and its projections

Extend the existing recording boundary in `src/runtime/node/inputs.ts` and `src/core/input-manifest.ts`; paths below starting `src/` are relative to `packages/@overeng/genie`. There MUST NOT be a second recorder or an independent import/path scan for the new artifact.

```text
discovery → imports/execution → render/compare → validators
                         │
                  one recording
                    ├─ read-set JSON + reason report
                    └─ GENIE_INPUT_MANIFEST + same-run metadata
```

The recording MUST retain file content observations, explicit absences, sorted directory inventories (names AND types, including empty directories), existence/type/stat observations that affect results, symlink/resolution observations, environment observations, and provenance. Imported files, non-import runtime reads, ignored/discovery inputs, workspace/lock/patch data, generated targets, and validator inputs are all inputs. Import metafiles alone are insufficient.

`GENIE_INPUT_MANIFEST` MUST become a projection of this same recording: its normalized path set MUST equal exactly the union of the read-set's file-entry and directory-entry paths, including absence entries. Its existing complete/incomplete header MUST reflect the same completeness decision; it is not independently reusable proof. Both outputs MUST carry a shared invocation identifier (legacy text may use a same-run metadata companion without changing its path-line grammar). No output may be assembled from another run or from a second post-run census. When only the legacy output is requested, the shared recorder MAY operate in path-only mode; that mode MUST NOT claim to have produced digest evidence.

## Closed incompleteness vocabulary

`reasons[].code` MUST be exactly one of the following closed enum values. Unknown values are a schema error; adding a value requires a schema-version change. An unclassified read/capability MUST produce its own `unknown-capability` occurrence with the observed operation and origin, NEVER silently disappear into `complete:true`.

| Code                   | Meaning                                                                                                                                                                               |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `unmediated-fs`        | File bytes, metadata, existence, directory inventory, or `Bun.file` access outside the recording API.                                                                                 |
| `unmediated-realpath`  | Physical-path/symlink resolution outside the recording API.                                                                                                                           |
| `subprocess`           | Child execution whose complete influencing input closure is not recorded. Argv/output digests alone are insufficient.                                                                 |
| `network`              | Network-dependent input not recorded with a reusable identity and validation rule.                                                                                                    |
| `ambient-env`          | Unrecorded environment, cwd, platform, or ambient process-context lookup affecting results.                                                                                           |
| `dynamic-import`       | Runtime-selected module resolution/execution not fully represented in the recording, including searched alternatives/absences.                                                        |
| `native-addon`         | Native code with unrecorded input capabilities. Presence of an npm package name alone is not evidence that it executed.                                                               |
| `unstable-observation` | Repeated/pre/post observations disagree, or bytes cannot be associated with the state actually consumed.                                                                              |
| `capture-error`        | Recording, digesting, attribution, or artifact publication fails.                                                                                                                     |
| `unknown-capability`   | An unknown read, unrestricted module/hook with unproven input closure, or another influencing capability not classified above; includes clock/random inputs unless proven irrelevant. |

`complete:true` requires successful capture of the entire influencing closure and no reason occurrences. Capture completeness and check success are separate fields: reuse additionally requires a successful check; a fully observed failed check is still nonreusable and does not need a fictitious capability reason. Ordinary unrestricted generators/transitive helpers MUST default to `unknown-capability` until their closure is accounted for; absence of grep hits is not proof. A raw operation already present in the recording need not be a bypass, but a partial wrapper MUST NOT certify uncovered operations. All influencing bypasses MUST be reported, not only the first failure.

Each occurrence MUST include `code`, operation/detail, source module and file:line when available, and the sorted explicit list of affected generator paths. Shared engine observations apply to every affected generator; import/helper observations propagate to all importing generators; validator observations propagate to every generator whose result they validate. If attribution is uncertain, list every discovered generator and add `unknown-capability`. The per-repo report MUST expand those lists to concrete paths, group by code/source, and include occurrence counts. It MUST distinguish observed bypasses from conservatively unproven capabilities. Incomplete-but-successful checks publish this report; affected generators are not reusable passes.

## Artifact schema and canonical encodings

The artifact is UTF-8 JSON, with no BOM, duplicate object keys, non-finite numbers, unpaired Unicode surrogates, or unknown keys. All fields below are REQUIRED; `null` is allowed only where shown. `schemaVersion` is the integer **1**, the ONLY supported value in this specification. Any other value, unknown enum member/observation, missing field, or inconsistent discriminated union is rejected by producer and consumer. Integers in this notation are JSON safe integers unless described as decimal strings. `ReasonCode` is exactly the closed enum above.

```ts
type Digest = string // exactly "sha256:" plus 64 lowercase hexadecimal characters
type Path = string // absolute native-platform path, normalized with path.resolve
type Generator = string // repo-relative path, "/" separators, no "." or ".." segments
type By = Generator[] // sorted unique affected generator paths
type EntryType =
  'file' | 'directory' | 'symlink' | 'socket' | 'fifo' | 'character-device' | 'block-device'
type Missing = { state: 'absent'; error: 'ENOENT' | 'ENOTDIR' }
type CodeFile = { path: Path; digest: Digest }
type Identity = { version: string; files: CodeFile[] }
type FileObservation = { path: Path; by: By } & (
  { state: 'present'; digest: Digest; byteLength: number } | Missing
)
type DirectoryObservation = { path: Path; by: By } & (
  { state: 'present'; entries: { name: string; type: EntryType }[]; digest: Digest } | Missing
)
type EnvObservation =
  { name: string; present: false; by: By } | { name: string; present: true; digest: Digest; by: By }
type CwdObservation = { lexical: Path; physical: Path; by: By }
type SymlinkObservation = { path: Path; by: By } & ({ state: 'present'; target: string } | Missing)
type Ref = { kind: 'file' | 'directory'; path: Path }
type ResolutionObservation = {
  importer: Path
  specifier: string
  by: By
  outcome:
    | { kind: 'file'; lexical: Path; physical: Path }
    | { kind: 'builtin'; name: string }
    | { kind: 'missing' }
  candidates: Ref[]
  contextEnv: string[]
  resolverCode: CodeFile[]
}
type ToolObservation = {
  name: string
  executable: Path
  version: string | null
  files: CodeFile[]
  by: By
}
type StatValues = {
  dev: string
  ino: string
  mode: string
  nlink: string
  uid: string
  gid: string
  rdev: string
  size: string
  blksize: string
  blocks: string
  atimeNs: string
  mtimeNs: string
  ctimeNs: string
  birthtimeNs: string
}
type StatObservation = { path: Path; followSymlinks: boolean; by: By } & (
  { state: 'present'; type: EntryType; values: StatValues } | Missing
)
type Reason = {
  code: ReasonCode
  operation: string
  detail: string
  source: { module: string; line: number | null }
  generators: By
  evidence: 'observed' | 'unproven'
}
type GeneratorResult = {
  generator: Generator
  target: Path
  module: Identity
  outputDigest: Digest
}
type ReadSet = {
  schema: 'genie-check-read-set'
  schemaVersion: 1
  invocationId: string
  checkSucceeded: boolean
  complete: boolean
  repoRoot: Path
  argv: string[]
  generators: By
  generatorResults: GeneratorResult[]
  platform: { os: string; arch: string }
  genie: Identity
  bun: Identity
  envSalt: string
  files: FileObservation[]
  directories: DirectoryObservation[]
  environment: EnvObservation[]
  cwd: CwdObservation[]
  symlinks: SymlinkObservation[]
  resolutions: ResolutionObservation[]
  tools: ToolObservation[]
  stats: StatObservation[]
  reasons: Reason[]
}
```

`invocationId` is a lowercase canonical RFC 4122 UUIDv4. `argv` is the exact ordered effective genie check arguments, with `--read-set` and its destination removed; the consumer MUST compare it to its intended invocation. `platform.os`/`arch` equal Bun's `process.platform`/`process.arch`. `genie.version` is the full semantic version, `bun.version` is `Bun.version`; identity files are nonempty and include every executable, entry bundle, or loaded code/config file capable of changing that component's behavior. Their digests are over raw bytes. A dirty build cannot substitute a revision string for this list. Missing/unknown identity closure is `unknown-capability`, not a weaker identity. Each external tool lists the executable AND its wrapper/interpreter/module code closure; its ancillary inputs remain ordinary observations. `version:null` means unavailable; a non-null version is the tool descriptor's exact version string, compared to the consumer's current descriptor without executing arbitrary artifact-provided commands.

`By` lists MUST contain only entries of top-level `generators`. Empty attribution is permitted only if no generators were discovered; unknown attribution otherwise expands to every discovered generator. Present files are regular files after following symlinks; a wrong-type probe is represented by a stat observation, not fabricated absence. `Missing` records an actual failed operation and its exact error; `ENOENT` and `ENOTDIR` are distinct and must be reproduced during validation. Other IO failures are `capture-error`. An unconstrained existence probe of an absent path adds BOTH absent file and absent directory entries; a typed probe adds the applicable entry. Every directory/name and string is losslessly representable Unicode; non-UTF-8 names or unknown entry types make capture incomplete instead of being replaced or normalized.

### Directory inventory digest

Names are exact single directory entry names, without Unicode normalization, `"."`, `".."`, path separators, or NUL. Entry types come from lstat/Dirent without following symlinks and use exactly `EntryType`. Sort entries by lexicographic comparison of their unsigned UTF-8 name bytes (shorter prefix first); duplicate names are invalid. The `entries` array is stored in that order. Define `JCS(x)` as RFC 8785 JSON Canonicalization Scheme text, and `UTF8` as UTF-8 bytes with no BOM. The digest is:

`"sha256:" + lowercaseHex(SHA256(UTF8("genie-directory-v1\n") || UTF8(JCS(entries.map(e => [e.name, e.type])))))`

The prefix ends with exactly one LF byte (`0a`); the JSON has no trailing newline. An empty inventory hashes that prefix followed by `[]`. Names/types are unambiguously delimited by canonical JSON, not newline concatenation. The consumer enumerates the directory anew, applies this exact algorithm, checks the digest, AND checks that the stored entries reproduce it. A symlink target change is covered by a separate symlink observation whenever link resolution affects the result; directory membership alone is not sufficient.

### Environment/secret digest

**Every environment variable name is classified as secret-bearing for schema 1**, including innocuous-looking names; there is no public-value allowlist, name heuristic, or plaintext value field. Preserve name case exactly; ambiguous name aliasing on a platform is incomplete. `envSalt` is 32 cryptographically random bytes encoded as exactly 64 lowercase hexadecimal characters, fresh per invocation and stored in the artifact. It is a public salt, not a secret key. For each present variable:

`digest = "sha256:" + lowercaseHex(SHA256(UTF8(JCS(["genie-env-v1", envSalt, name, value]))))`

`value` is the exact consumed Unicode environment string, without trimming, normalization, or interpolation. Empty is `""`; unset uses `present:false` with no digest and is NOT the digest of an empty value. The consumer reads the current variable of the same exact name, checks presence, recomputes with the artifact's salt and the formula above, and compares the full digest bytes. Consumers MUST NOT generate a new salt for comparison. The recorder MUST NOT copy observed environment values into argv, reason detail, or report logging. If an independently secret-bearing argv input cannot be safely represented, publish only a redacted `unknown-capability` reason report and no reusable artifact; do not replace exact argv with a silently reusable redaction. Unreadable/unrepresentable observations are `capture-error`.

Salting prevents cross-artifact value correlation but does NOT prevent offline guessing of low-entropy values. The artifact, legacy metadata companion, and reason report are private local files, mode `0600`; they MUST NOT be published as public diagnostics. This format is not an authentication token or a substitute for the consumer's trust in its local artifact. A consumer on another machine/context still compares its own current values and identities, and misses on any mismatch.

### Other observations and validation algorithm

All observation arrays are deduplicated by their full identity key: file/directory/symlink by `path`, env by `name`, cwd by `lexical`, stat by `[path,followSymlinks]`, resolution by `[importer,specifier]`, tool by `name`. Repeated unequal observations at one key require `unstable-observation`; preserve a diagnostic occurrence rather than selecting whichever value makes reuse possible. `CodeFile[]` sort uniquely by path; `By` and name lists sort uniquely by unsigned UTF-8 bytes. Sort observation arrays by the UTF-8 bytes of JCS(identity key); reasons by JCS of the whole reason. These ordering rules affect serialization only, never execution order.

Cwd records each cwd actually used: consumer compares its intended invocation cwd (and any explicitly modeled cwd transitions) after lexical normalization and realpath. Any unmodeled transition is `ambient-env`. Symlink `target` is the exact readlink result, possibly relative, and is compared without normalization; non-symlink replacement is a mismatch. Stat values are canonical base-10 signed integer strings (`0` or `-?[1-9][0-9]*`, no leading plus/zeros), using bigint stat fields and integer nanosecond timestamps. Consumer repeats stat or lstat according to `followSymlinks` and compares type and EVERY recorded value. If any field cannot be obtained exactly, record `capture-error`. Unmodeled filesystem operations such as statfs cause `unknown-capability`.

Resolution `candidates` retains actual search-priority order; each reference MUST exist in the matching top-level file/directory array, including absent alternatives. `contextEnv` references recorded environment names; `resolverCode` identifies every influencing resolver/import-map implementation by bytes. File outcomes MUST reference recorded file bytes at the physical target and all traversed link observations; builtins use canonical `node:` names. A complete resolution record requires all influencing search inventories, package/import-map bytes, options/context, and resolution alternatives in the recording; otherwise report `dynamic-import`/`unknown-capability`. The consumer validates those observations and resolver identities; it does not execute generator imports to rediscover a resolution. A resolver without a closed recorded input model cannot produce a complete artifact.

For reasons, `source.module` is a repo-relative source path or a dependency module specifier, `line` is a positive 1-based line or `null` if unavailable, and `operation`/`detail` contain non-secret diagnostics. A report uses the same reasons, source locations, and expanded `generators` lists as the artifact. `complete` MUST equal `reasons.length === 0`; it does not imply `checkSucceeded`. Unsupported observations and provenance gaps add their own reason, never disappear during serialization.

Capture begins before the first influencing read and ends after validators. Hash consumed bytes and check stability, not merely a later census. Exclude output destinations/temporary paths from discovery and self-recording. Publish with same-directory temporary files and atomic rename. A failed check MUST NOT store a result or artifact and MUST remove any stale successful artifact before returning; its reason report MAY still be published. Publication faults are `capture-error` and MUST NOT create reusable success. If no valid artifact can be written, fail output publication and leave no reusable previous artifact. The same run identifier in the legacy metadata companion gates pairing; the consumer reads both and rejects mismatched IDs.

Producer and consumer independently validate the exact schema, ordering, unique keys, referenced paths, digest formulas, reason/complete invariant, and identities. Producer also requires stable consumed observations. Reuse requires `checkSucceeded:true`, an eligible same-run artifact, and matching intended argv/root; completeness, identities, and observations are then checked per generator as below. Validation itself MUST observe stable state; a changed/uncertain/unreadable observation is a miss. Unsupported versions/classes, malformed/truncated/missing/stale artifacts, or discarded observation classes are a miss. On a miss, re-run the affected generator; invalid invocation-wide evidence re-runs every generator. This specifies a validation algorithm, not a consumer-specific cache implementation.

### Per-generator reuse

The reuse unit MUST be one generator invocation for one target, identified by `GeneratorResult.generator` and `target`. `generatorResults` MUST contain exactly one entry per such pair, sorted uniquely by the UTF-8 bytes of JCS of that pair. `module` records the generator module's identity by bytes, including its influencing module closure; `outputDigest` is the digest of the successfully checked generated bytes. Each unit's read set is the observations attributed to its generator by `by`, including shared engine and validator observations. It MUST include the target file itself. Reads of other generators' outputs MUST be recorded as explicit file-observation edges attributed to the reading generator, referencing the producing generator's target. These edges MUST NOT imply or introduce execution ordering.

Per-generator identity MUST consist of the genie build identity, generator module identity, platform/Bun identities, and only that generator's own environment observations (including shared observations attributed to it). An unrelated generator's module or environment change MUST NOT by itself invalidate this identity; influencing tool identities remain recorded observations.

A generator MUST pass by reuse only when all three conditions hold:

1. Its recorded read set is complete: no reason occurrence names that generator, and its entire influencing closure is recorded. An incomplete read set MUST always re-run that generator and MUST NEVER be reused, even when all recorded observations match.
2. Every recorded observation in that read set, including its identity and explicit output-read edges, equals the current observation under the validation algorithms above.
3. The current target file digest equals its recorded `outputDigest`.

If any condition fails, that generator MUST re-run. Invocation-wide `complete:false` does not prevent reuse of another generator whose own read set is complete. The invocation MUST retain one check result, combining reused and re-run generators under the unchanged validation policy. One failed generator MUST fail that check; no failed result is stored. A newly published artifact MUST describe the current invocation, including revalidated observations for reused generators, not splice evidence from another run.

## Opt-out cost and acceptance

With neither `--read-set` nor `GENIE_INPUT_MANIFEST` requested, the recording layer MUST NOT be installed: no recorder/state allocation, new source scan, hashing, directory census, or artifact IO. Dispatch MUST choose the existing uninstrumented check before creating recorder/services. With only the legacy environment output requested, retain its explicit path-recording cost but add no read-set hashing; both requested outputs use one recorder. This qualification preserves the existing opt-in feature rather than silently disabling it.

Required acceptance tests:

1. A closed, fully recorded fixture produces `complete:true`; unchanged inputs may be reused. Mutate exactly one class per case: transitive import, runtime/validator-only file, absent file becoming present, directory entry added, entry removed, env value/unset/empty, genie build identity with unchanged semver, Bun/tool/platform identity, cwd, member symlink/resolution alternative, and generated target bytes. Each mutation MUST force the affected generator to re-run.
2. Exercise every enum reason, including direct fs, raw realpath, `Bun.file`, unknown reads, arbitrary child/network/native capability and dynamic import fixtures. Require the correct code, source, and expanded affected-generator list; unknown capability MUST never yield complete proof. Concurrent/conflicting reads and injected capture/publication failures MUST fail closed. No containment is added to make these tests pass.
3. Request both outputs in ONE check. Assert shared invocation ID, identical completeness decision, and exact equality of legacy path lines to the read-set file/dir path union, including absences. Test failure/incomplete output and mismatched-run rejection. Assert only one recording is installed.
4. Verify producer and consumer rejection of malformed/truncated/missing/unsupported/failed/stale evidence and unsupported observation classes; incomplete evidence MUST prevent reuse of each affected generator. Test per-repo reports for shared helpers, validator propagation, conservative unknown attribution, and all bypasses reported together.
5. Per-generator mutation tests MUST independently falsify each reuse condition: introduce an incompleteness reason while keeping recorded observations and target bytes unchanged; change one recorded observation while retaining completeness and target bytes; and change the target digest while retaining the other observations. Each MUST re-run the affected generator rather than reuse it. An unaffected complete generator MUST remain reusable in the same invocation, including when its peer is incomplete. Also test mixed reused/re-run results, explicit reads of another generator's output without implicit ordering, generator-local module/env identity changes, and one failed generator failing the combined check with no failed result stored.
6. Opt-out structural tests MUST prove no recorder installation and no hashing when neither output is requested. Measure `genie --check` WITHOUT the flag and with the legacy env unset, before/after the implementation: same fixed clean source/tool/input state, normal admission, at least three interleaved pairs warm and cold-ish, wall and process user+sys CPU, medians/spread and concurrent-holder receipts. Prespecify noise from interleaved baseline/baseline controls; the unflagged change MUST remain within that measured noise, not claim literal zero elapsed difference. A repeatable regression blocks acceptance.

Conformance requires the acceptance evidence above; the specification itself is not evidence that recording or reuse is implemented.
