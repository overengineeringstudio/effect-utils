# 2026-07-01 — Two-layer design (Layer 1 foundation + Layer 2 Effect-Schema authoring)

Durable record distilled from `tmp/weaver-experiment/proto/two-layer/` (deletable). Run
against the REAL `@overeng/otel-contract` and validated by the from-source Weaver **0.24.2**
flake.

## Hypothesis

The semconv generator can be split into a Layer 1 foundation (direct Weaver registry model)
and a Layer 2 that embraces Effect Schema, where **attributes are real annotated Effect
Schemas** and one authored value derives BOTH the Weaver registry AND the runtime encoder —
recovering otel-contract's ergonomics without giving up the registry contract.

## Method

- `layer1.ts` — plain typed Weaver model (`AttrDef`/`SignalDef`/`AttributeGroup`) +
  deterministic YAML. No Effect-Schema dependency. Standalone.
- `layer2.ts` — `attr.string`/`attr.enum` return REAL Effect Schemas (built on
  `OtelAttr.string`/`OtelAttr.literal`) carrying BOTH the otel annotation (key/cardinality/
  encode) AND a new weaver annotation (brief/stability/examples/type). A `toAttrDef`/
  `toRegistry` projector reads the AST → Layer 1 data. `span(...)` composes attribute refs,
  deriving the Weaver signal group AND the runtime encoder via otel-contract's own
  `OtelAttrs.defineSync`.
- `prove-2l.ts` — one authoring surface; assert all three outputs.

## Results (all ✅)

1. Layer 2 authoring → Layer 1 registry → `weaver registry check --future` **clean** (0.24.2).
2. Runtime encoder from the SAME source → `{restate.service, restate.object.key,
restate.error.class}` (otel-contract machinery, identical).
3. Full Effect-Schema ergonomics preserved: `Schema.decode` on an attribute works; bad enum
   value rejected; the attribute **composes into arbitrary `Schema.Struct`s**
   (`Schema.Struct({ svc: RestateService, when: Schema.DateFromString })` decodes).

## Conclusion

The two-layer split is validated and is the design of record:

- **Layer 1** is a faithful, standalone Weaver-registry foundation (usable directly for
  decoupled / doc-only / hand-tuned cases).
- **Layer 2** recovers otel-contract's Effect-Schema ergonomics (attributes ARE Schemas,
  composable/decodable/transformable) AND derives the registry + runtime encoder from one
  annotated value, via AST annotations — the mechanism otel-contract already uses.

Because Layer 1 is standalone and Layer-2 derivation is opt-in, the earlier "over-coupling
of a public API and a private encoder" concern is answered by construction: derivation is a
per-attribute/per-namespace choice, not a forced architecture.
