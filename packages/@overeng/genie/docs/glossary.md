# Genie Glossary

Canonical terms for the `@overeng/genie` subsystem. Generator-specific terms live in [generators/glossary.md](./generators/glossary.md).

- **Bootstrap** — the phase in which Genie runs before package-manager install state exists (fresh checkout / CI), when `node_modules` and generated workspace state may be absent. See requirements R05–R07.
- **Bootstrap-safe import closure** — the set of modules transitively reachable at runtime from a `.genie.ts` source, all of which must be importable during bootstrap. A `.genie.ts` satisfies the contract when its entire closure is bootstrap-safe (R06).
- **Runtime-only package** — a package whose value imports require an installed dependency graph and so is unavailable during bootstrap (e.g. `effect`, `@effect/platform`, `typescript`). A generator closure must not reach one.
- **Closure boundary** — a bare specifier (non-relative, non-`#`/`#mr`, non-node-builtin) encountered while walking a closure. It is the reported violation, not an edge to follow, so the walk never descends into `node_modules`.
- **Type-only edge** — an import/export erased at compile time (`import type`, `export type`, `export type *`, or a fully per-specifier `{ type X }` list). Excluded from the runtime closure because it does not exist at runtime.
- **`#mr/<member>/...`** — a megarepo member import resolved against `megarepo.lock` to the member's global store worktree (lock-pinned identity), rather than a bare package name or a `repos/` symlink. The bootstrap-safe way for a generator to reach another member's source. See spec _Import Resolution_.
- **Generator phase** — a per-generator property: `bootstrap` (runs before install; must be bootstrap-safe per R06) or `design-time` (runs after install; may use the runtime graph, e.g. Effect-Schema semconv authoring). `design-time` is the default; `bootstrap` is opt-in, declared statically so it is discoverable without importing the generator.
- **`@genie-bootstrap`** — the static source pragma marking a `.genie.ts` bootstrap-phase. A namespace-prefixed valueless flag mirroring TypeScript pragma grammar (`@ts-nocheck`/`@ts-check`), placed in the leading comment block and read from raw source (no import). `design-time` needs no marker (it is the default).
- **Bootstrap-phase generator** — a generator whose output an install step depends on, so it must be runnable before install; the bootstrap-closure contract (R06) applies to it. Declared with `// @genie-bootstrap`; checked statically by the closure gate (R30) and demonstrated empirically by the cold-proof (R32).
- **Design-time generator** — a generator that runs after install and may depend on the runtime graph; out of scope for the bootstrap-closure contract by declaration (not by allowlist).
- **`bootstrap:cold-proof`** — the CI job that demonstrates the bootstrap contract is real: a fresh checkout with no `node_modules` runs the bootstrap-phase generators with the self-contained nix bootstrap runner, then `pnpm:install`, asserting both succeed (R32). It is the authority; the static gate is fast feedback. (Supersedes the earlier `genie:bootstrap`-before-`pnpm:install` edge, which is removed — decision 0004: install ordering does not arbitrate here.)
- **Baseline + ratchet** — the _former_ (interim) enforcement mode for the bootstrap-closure check: pre-existing violations captured in a committed baseline, only new ones fail. Removed by decision 0004: the check is now scoped to bootstrap-phase generators and zero-tolerance (no baseline). Kept here only to explain historical references.
