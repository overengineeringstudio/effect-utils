Notion tooling · primitive 03

notion schema — typed, versioned, drift-checked access

Introspect a Notion database into typed Effect schemas, commit them, and let a CI gate fail the build when Notion drifts away from your code.

The gap

The Notion API hands you untyped JSON. Property names, option sets, and types live only in the workspace — so your code guesses at shapes, and a rename in Notion breaks you at runtime with no warning.

The stopgap

schema generate introspects a DB into a typed schema.gen.ts — literal-union options, write schemas, a typed API. generate-config declares many DBs at once; diff --exit-code is a CI drift gate that fails when Notion no longer matches your committed types.

Command / flagWhat you get
schema generate <id> -o x.gen.tstyped read schema for the database
--typed-optionsliteral-union types for select / status options
--include-writetyped create / update property payloads
--include-apityped queryAll · get · create · update wrapper
generate-configdeclare many databases in one config file
diff --exit-codeCI drift gate — exit 1 when Notion ≠ your types

What first-class would look like: Notion publishing typed, versioned schema bindings with server-side drift alerts. Be clear about what this is: introspect → codegen → drift detection, not declarative provisioning. You still create and change the database in Notion — the CLI mirrors it into your types and fails CI when the two disagree.
