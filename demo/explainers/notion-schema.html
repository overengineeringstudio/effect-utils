The API returns untyped JSON — property names, option sets and types live only in the workspace. Your editor can't autocomplete them, and a rename in Notion sails past tsc to break you at runtime, with no warning.

notion schema generate introspects the live database and writes a typed .gen.ts. --typed-options gives every select / status a literal-union type; --include-api emits a companion tasks.gen.api.ts wrapper. Now your editor autocompletes every property and option.

Commit the generated schema and it's just code — versioned, reviewed in PRs, type-checked end to end. queryAll · get · create · update are all typed against the real database, so a wrong property name or option fails at compile time, not in production.

Be honest about what this is: introspect → codegen → drift detection, not declarative provisioning. You still create and change the database in Notion. notion schema diff <id> --file tasks.gen.ts --exit-code mirrors the live DB against your committed types and fails CI (exit 1) the moment they disagree — so drift can't silently ship.

What first-class would look like: Notion publishing typed, versioned schema bindings with server-side drift alerts. Until then, notion schema fills the gap.
