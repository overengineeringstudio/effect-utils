Notion tooling · the thread

The Notion dev platform — and the four walls you hit

Notion's API, CLI, and Workers are genuinely good. But try to build something advanced on them and you keep hitting the same four walls. Here's the map — and the tool that fills each gap.

01The problem

The platform is good — until you build something advanced on it.

Notion dev platform
✓APIpages · blocks · data sources
✓CLIntn — scriptable access
✓Workersin-workspace automation
✓ a genuinely capable substrate
💥
push past the basics
…and you hit the same four walls
✗No local sync for Markdown ⇄ pages
✗No tabular editing — no SQL, no diff
✗No typed access — untyped JSON
✗No declarative pages — raw block ops

The developer platform — REST API, the ntn CLI, in-workspace Workers — is a capable substrate. But push past basic reads and writes and the same four gaps recur: local sync, tabular editing, typed access, and declarative pages.

02The map

Four gaps, four tools — each fills a wall Notion hasn't shipped yet.

01 notion md
≡ local .md⇄▤ Notion page

GapNo first-class way to keep local Markdown in sync with pages — either side can silently clobber the other.

FillAn .nmd source of truth with a 3-way merge; divergence writes a conflict draft instead of overwriting.

02 notion db
⌘ SQL⇄▦ Notion DB

GapNo way to edit a database as tabular, scriptable data — no SQL, no diffable file.

FillA local <db-id>.sqlite replica you edit with plain SQL; a guarded sync fails closed on unsafe writes.

03 notion schema
▦ Notion DB→‹› tasks.gen.ts

GapThe API hands you untyped JSON; a rename in Notion breaks you at runtime with no warning.

FillIntrospect into typed Effect schemas; a diff --exit-code CI gate fails the build on drift.

04 notion-react
‹› JSX→▤ Notion page

GapThe block API is raw imperative append/update/delete — re-rendering means churn or a hand-rolled diff.

FillWrite pages as JSX; a reconciler diffs by blockKey and emits the minimum block ops.

Each tool is a small, sharp fill for one gap. Local sync (notion md), tabular editing (notion db), typed drift-checked schemas (notion schema), declarative pages (notion-react) — one wall each.
