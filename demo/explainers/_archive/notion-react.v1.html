Notion tooling · primitive 04

notion-react — write Notion pages as JSX

Render a page as a React tree; a react-reconciler diffs it against the last sync and emits the minimum set of Notion block operations.

The gap

Notion's block API is raw and imperative: append / update / delete against block ids. To re-render a page you either wipe and re-append every run (visible churn, O(blocks) cost) or hand-roll a keyed diff, a cache, and a kill-switch.

The stopgap

Write the page as JSX. A react-reconciler matches each element to a previously-synced block by blockKey: added ⇒ create, removed ⇒ archive, moved <ChildPage> ⇒ pages.move. Re-rendering identical JSX is a no-op.

Change to the JSX treeNotion ops emitted
Re-render identical JSX0 ops
Change one block's props1 update
Append a sibling1 append
Remove a sibling1 archive
Move a <ChildPage>1 pages.move
Manual edit in Notionoverwritten next sync — tree is source of truth

What first-class would look like: Notion offering a declarative, diffable page API — hand it a tree, get the minimum ops. Until then, notion-react is that reconciler: JSX in, minimum Notion ops out, with the diff keyed on blockKey so identity survives across process restarts.
