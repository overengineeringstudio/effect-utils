Notion tooling · primitive 02

notion db — edit a Notion database as local SQL

Point sqlite3 at your Notion database, edit rows with plain SQL, and sync the changes back through a guarded planner that fails closed on anything it can't prove safe.

The gap

Notion gives you a web grid or a REST API of typed property objects. There's no first-class way to treat a database as tabular, scriptable data — no SELECT, no bulk UPDATE, no diffable file you can script against.

The stopgap

track pulls the database into a self-contained <db-id>.sqlite replica. Edit the rows table with ordinary SQL; sync plans, verifies, and applies each write back. Unsupported writes fail closed — never silently dropped.

What first-class would look like: Notion exposing a real tabular surface — transactional SQL over a database with typed columns and a proper write contract. Until then, notion db gives you sqlite3 plus a sync that refuses to corrupt your data.
