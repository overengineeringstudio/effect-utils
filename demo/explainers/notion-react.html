notion-react — write Notion pages as JSX

Describe a page as a React tree. A reconciler diffs it against the last sync and emits only the block ops that changed — no rebuild, no hand-tracking block ids.

Notion's block API is raw and imperative — append / update / delete against block ids. To re-render a page you either wipe and re-append every block each run (churn, flicker, O(blocks) cost) or hand-roll a keyed diff, a cache, and a kill-switch yourself.

04…and identity holds

Every block carries a blockKey. That's how identity survives a restart.

b:scope→block_c3d4…

move a <ChildPage>pages.move contract

The diff is keyed on blockKey, not sibling position. Each rendered block matches a previously-synced Notion block through the persisted FsCache (.notion-cache.json) — so a match reuses the real block id, and identity holds across process restarts. add→create, remove→archive, change→update. Page-level pages.move is the designed contract (block ops ship today; page ops are next).

What first-class would look like: Notion offering a declarative, diffable page API — hand it a tree, get the minimum ops. Until then, notion-react is that reconciler: JSX in, minimum block ops out, keyed on blockKey.
