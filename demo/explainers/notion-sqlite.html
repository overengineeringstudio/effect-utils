The whole flow, in four steps

  1. 1Your Notion database, as a local SQLite file.
  2. 2Edit a row with plain SQL — locally.
  3. 3One guarded sync pushes it.
  4. 4…and it lands in Notion, live.

notion db track pulls the database into a local <db-id>.sqlite. Edit the pages table with ordinary SQL, run notion db sync — the write lands on the real Notion row. Each write is read-after-write verified before it settles. Two-way push needs --mode shared at track time.

04…and it fails closed

A write Notion can't take safely? A typed refusal — never lost data.

Status → Done · verified in Notion

Every write is checked before it touches Notion. Formula/rollup writes and hard DELETEs are refused as a typed GuardBlocked event with a named guard (ComputedPropertyWrite, DeleteVsEdit) — blocked until the behavior is proven safe, never silently dropped. Writable cells sail through, verified.

What first-class would look like: Notion exposing real transactional SQL over a typed database. Until then, notion db gives you sqlite3 plus a sync that refuses to corrupt your data.
