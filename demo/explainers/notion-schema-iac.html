notion schema apply — provision your Notion database from a file

The honest inverse of codegen (3.1). Instead of generating code from Notion, declare the database you want in a typed file and have the tool reconcile Notion to match — additive and safe. This is a designed preview of where notion schema is headed, not a shipped feature.

The planned flow, in four steps

  1. 1Declare the database you want — in a typed file.
  2. 2Plan shows exactly what it would create — before touching anything.
  3. 3Apply would provision it — reconciling the delta on every run.
  4. 4Additive only; anything that could lose data is refused.
Re-run after editing the file → ~ add option to "Priority" (+ Urgent)  ·  + property "Blocked" checkbox unchanged file ⇒ no-op

The whole arc is narrated mock output driving a projected Notion — nothing here is a live capture. plan prints every change it would make (+ add, ~ change), creating nothing; the first apply would create the DB and write a tasks.notiondb.lock.json; re-runs reconcile only the delta. The planner, the lock/state model and these commands are the parts that aren't built yet.

✓ real today · the engine

The sync layer already adds properties, renames them, extends select options, and refuses destructive changes against a live Notion DB. Those guard names are the actual ones in notion-datasource-sync.

◷ planned · the front-end

What's not built: the declarative plan/apply commands, the planner that diffs a file against Notion, and the lock.json state model. A front-end doesn't get to weaken the guards.

This is why the direction is even worth considering: the boundary is inherited from an engine that already fails closed today. Deletes, type changes and option removals are done deliberately in Notion — never as a silent side effect of editing a file. And to be clear once more: this front-end is planned work; the engine exists, the commands don't.

Planned / roadmap preview — notion schema apply and notion schema plan do not ship today. The shipped inverse is 3.1 codegen (notion schema generate · DB → code). This page is the honest code → DB direction we'd build on top of the same engine.
