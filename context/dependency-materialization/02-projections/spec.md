# Projection Spec

This document specifies dependency projection. It builds on
[requirements.md](./requirements.md).

Status: **Draft**

## Scope

This spec defines deterministic projection after dependency data exists:

- `.bin` link creation;
- projection reports;
- stale projection repair;
- the prepared-deps exclusion boundary.

## Bin Projection

```text
realized node_modules graph
  + package manifests
  + projection policy
  -> node_modules/.bin
  -> projection report
```

The projector:

1. enumerates package roots visible to the selected workspace package;
2. reads each `package.json`;
3. normalizes string and object `bin` fields;
4. validates that each target exists;
5. creates a symlink or shim according to the platform policy;
6. records the created, repaired, skipped, and rejected entries.

The projector does not import package modules, execute package scripts, or call
pnpm build commands.

## Report Shape

```json
{
  "schema": "dependency-projection-report/v0",
  "profileId": "pnpm:...",
  "projection": "bin",
  "policy": "pure-manifest",
  "entries": [
    {
      "name": "tsc",
      "packageName": "typescript",
      "target": "node_modules/typescript/bin/tsc",
      "link": "node_modules/.bin/tsc",
      "status": "created"
    }
  ],
  "rejections": []
}
```

Paths are repo-relative in public reports.

## Edge Cases

The projection contract covers:

- scoped package names;
- string and object `bin` fields;
- dependency aliases where the dependency key differs from the package name;
- workspace package bins;
- executable bit and shebang preservation on Unix;
- deterministic repair of stale owned shims.

Package CLIs generated by postinstall are not projection inputs. They require a
Nix/native integration or a pure package artifact classification.
