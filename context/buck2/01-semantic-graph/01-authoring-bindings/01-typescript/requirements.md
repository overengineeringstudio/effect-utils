# TypeScript Authoring Binding Requirements

**Role:** This binding composes existing Genie package, TypeScript project, and
operation authorities into a TypeScript contribution to the parent
[authoring-binding contract](../requirements.md). It does not own package
resolution, BUCK rendering, or TypeScript target execution.

## Context

Generated `package.json` and `tsconfig` files are projections. Their
`.genie.ts` sources remain the native authoring chain. Buck operations add only
operation intent and exact use edges to declarations already owned by that
chain.

## Assumptions

- **BUCK.GRAPH.BIND.TS-A01 Genie authority:** Existing Genie composition owns
  package manifest and TypeScript project facts and continues to emit their
  current default projections.
- **BUCK.GRAPH.BIND.TS-A02 Shared binding:** The contribution satisfies
  `BUCK.GRAPH.BIND-R01` through `BUCK.GRAPH.BIND-R09`.

## Acceptable Tradeoffs

- **BUCK.GRAPH.BIND.TS-T01 Compile-time brands:** TypeScript brands may improve
  authoring safety, but runtime validation of structural values remains
  authoritative.
- **BUCK.GRAPH.BIND.TS-T02 Peer exclusion:** Peer dependency declarations do
  not produce operation roots until a peer-context contract defines their
  resolver meaning.

## Requirements

### Must compose narrow existing facets

- **BUCK.GRAPH.BIND.TS-R01 Package facet:** Package composition must retain an
  immutable, non-emitted facet for package identity and canonical direct
  dependency declarations before generated manifest maps widen.
- **BUCK.GRAPH.BIND.TS-R02 Project facet:** TypeScript project composition must
  expose only semantic project identity, configuration, project references,
  and typed file-set intent required by the graph. Generated `tsconfig` bytes
  must not be reparsed as authority.
- **BUCK.GRAPH.BIND.TS-R03 Operation facet:** Package-local Buck authoring must
  define operations and their irreducible references to package and project
  facets. It must not redefine dependency requests, project configuration, or
  generated manifest fields.
- **BUCK.GRAPH.BIND.TS-R04 One-way imports:** Pure helpers and native facets may
  flow into operation authoring and projections. Package or project authority
  must not import operation authoring, BUCK projection, or target execution.

### Must preserve exact dependency identity

- **BUCK.GRAPH.BIND.TS-R05 Field-qualified handles:** Rootable direct
  declarations must expose stable handles qualified by owning package,
  manifest field, and alias, preserving external versus workspace provenance
  and logical first-party identity.
- **BUCK.GRAPH.BIND.TS-R06 Exact operation uses:** Each operation must select
  its exact handles. Unknown, peer-only, foreign-package, and invalid-field
  references must fail before graph projection.
- **BUCK.GRAPH.BIND.TS-R07 Narrow runtime values:** Handles must not contain
  selected versions, resolver contexts, physical paths, private workspace
  topology, callbacks, or mutable identity.

### Must preserve Genie behavior and scale

- **BUCK.GRAPH.BIND.TS-R08 Default projection parity:** Introducing facets and
  operation uses must preserve existing package and project generated bytes
  unless their authoritative inputs change.
- **BUCK.GRAPH.BIND.TS-R09 Repeated-evaluation purity:** Facet construction and
  composition must remain deterministic when Genie evaluates imported modules
  repeatedly or in a different discovery order.
- **BUCK.GRAPH.BIND.TS-R10 Generic erasure:** Package-specific handle unions
  must be erased at operation normalization so declaration size and type-check
  memory do not scale across the repository graph.
- **BUCK.GRAPH.BIND.TS-R11 TypeScript admission controls:** Retained controls
  must cover literal-key safety, field collisions, byte parity, import cycles,
  repeated evaluation, privacy, foreign references, type-scale bounds, and
  relevant versus irrelevant invalidation.
