# Genie Dependency SSOT Prototypes

Status: completed; evidence for interview Q15 refinement

## Question

Can exact operation-local dependency roots reuse and recompose the existing
`package.json.genie.ts` source-of-truth chain without repeating dependency
declarations, versions, or resolver data?

## Candidates

| Candidate                                                | Result                | Main finding                                                                                                                |
| -------------------------------------------------------- | --------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Named typed semantic export from the existing Genie file | Pass                  | Direct typed imports, zero repeated versions/maps, narrow projection bytes, and fail-closed root references                 |
| Typed extraction from `GenieOutput.data`                 | Pass with limitations | Byte-compatible and useful for migration, but widened string keys lose compile-time alias safety and composition provenance |
| Dependency declarations name their consuming operations  | Correct but rejected  | Avoids operation lists, but creates reverse consumer knowledge, rename fanout, and cyclic composition pressure              |

## Typed Export Prototype

`package.json.genie.ts` exported one typed semantic value and defaulted its
package JSON projection. BUCK and tsconfig projections imported the typed value
directly rather than parsing generated bytes.

The prototype used 54 nonblank, noncomment authored lines across a catalog, two
package definitions, and two projection consumers. Each consumer was three
lines. It repeated no dependency map and no version literal.

| Oracle                                      | Result |
| ------------------------------------------- | ------ |
| Strict TypeScript checking                  | Pass   |
| Direct typed reuse                          | Pass   |
| No generated-output parsing                 | Pass   |
| Undeclared-root rejection                   | Pass   |
| Irrelevant-facet byte stability             | Pass   |
| Operation edit changes only Buck projection | Pass   |
| Package-local isolation                     | Pass   |

## Output Extraction Prototype

Extracting dependency fields from the existing structured Genie output
preserved checked-in package JSON bytes through the normal formatter and
preserved a 1,604-byte BUCK projection exactly. Check and test operations each
selected two roots; an irrelevant package-only edit changed package JSON but
left BUCK bytes and roots unchanged.

Direct output inspection is not the long-term API because dependency keys widen
to `Record<string, string>` and the output no longer retains workspace/external
composition provenance. A supported typed facet on the same Genie value avoids
both defects.

## Dependency-Use Direction Prototype

The bounded oracle covered six operations across pnpm and Cargo, including two
same-role tests with different roots, eight declarations, and sixteen request
or alias mutations.

| Model                                       | Exact roots        | Same-role difference | Rename locality                            |
| ------------------------------------------- | ------------------ | -------------------- | ------------------------------------------ |
| Operation references typed handles          | Pass               | Pass                 | One declaration edit                       |
| Role-only applicability                     | Fail: over-selects | Fail                 | One declaration edit                       |
| Dependencies reference consuming operations | Pass               | Pass                 | Operation plus dependent declaration edits |

The operation-to-handle projection was byte-identical across equivalent
ordering and repeated runs. Its canonical output digest was
`29514acf015ccdbce0812417932fa76ec1e5cbd5f365c12eb98e556a5a305453`.

## Conclusion

Extend the existing Genie package composition with a named typed semantic
facet. Dependency declarations produce stable branded handles carrying their
request identity and ecosystem refinement. Operations reference those handles;
this authors only the irreducible use edge and does not duplicate dependency
data. BUCK, package JSON, and other projections consume narrow facets so an
irrelevant facet edit remains byte-stable.

Parsing rendered package JSON is forbidden. Inspecting widened output data is a
migration adapter only. Role-wide defaults may be authoring sugar only when
they normalize into explicit operation-to-handle edges before semantic
identity.
