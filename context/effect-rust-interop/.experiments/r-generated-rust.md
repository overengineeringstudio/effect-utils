# Experiment R: Generated Rust shape and ergonomics

## Question

Which generated Rust shape best preserves invariants, diagnostics, tooling, and migration feedback?

## Hypothesis

Typed, invariant-preserving Rust can match the owner semantics while differing materially in paths, tooling, dependency cost, and evolution behavior.

## Method

Compared A (serde plus own newtypes), A-stream (streaming tagged unions), B (non-exhaustive plus constructors), C-nutype, C-garde (two-phase validation), and D (contract-expansion proc macro). Seven roots covered B1 scalars/presence, content descriptors, tagged events, recursive trees, and recursive expressions. Each shape and the Effect reference executed 125 vectors. Separate JSON-text probes, v2 consumer recompilation, rust-analyzer LSP, and build CPU measurements exercised boundaries beyond value parity. Pins: Rust 1.98.1, Effect 4.0.0-rc.118, Bun 1.4.2.

## Result

All six shapes and Effect had zero shared-vector disagreements and zero canonical semantic round-trip failures. Generated ordinary-source shapes regenerated byte-identically.

| Metric                                  |    A | A-stream |    B | C-nutype | C-garde |    D |
| --------------------------------------- | ---: | -------: | ---: | -------: | ------: | ---: |
| Nested error paths / 89 rejections      |   59 |       72 |   59 |       59 |      65 |   59 |
| Root-only union paths / 20              |   16 |        3 |   16 |       16 |      14 |   16 |
| Dependency crates                       |   22 |       22 |   22 |       33 |      33 |   26 |
| Cold consumer CPU-s, median of 3        | 34.4 |     35.3 | 32.8 |     64.4 |    49.1 | 43.5 |
| Incremental contract CPU-s, median of 5 | 0.75 |     0.77 | 1.06 |     0.60 |    0.71 | 0.60 |
| v2 unchanged-consumer compile errors    |    3 |        3 |    0 |        3 |       3 |    3 |

A-stream used 706 generated lines versus A's 654; consumers used 143 lines each. B consumers compiled after additions but classified new variants as unknown. C-garde allowed invalid values to exist until validate(); D's go-to-definition landed in the proc macro and external expansion was not linted. Nutype had weaker constraint messages and more host dependencies.

Five parser probes disagreed across every shape: integer `1.0`, exponent `1e2`, duplicate keys, duplicate `_tag`, and depth 200. The chrono precision probe encoded nanoseconds as milliseconds with round-trip equality false. Sorted Rust record keys differed bytewise from Effect insertion order. A-stream preserved nested paths when `_tag` came first; tag-last fell back to Value and lost paths.

## Conclusion

[Decision 0009](../.decisions/0009-generated-rust-shape.md) selects A-stream, exhaustive by default, a separate crate per set, named constrained strings, TimestampMillis, and Patch<T>. [Decision 0010](../.decisions/0010-json-control-plane.md) closes parser-profile and ordering choices while retaining the explicit tag-first friction bakeoff.

## Intent Impact

Replaces dynamic generated trees with the typed A-stream contract and exposes parser-level obligations outside object-vector parity.

## Limits

The IR and Effect reference schemas were hand-authored, not production owner-to-IR output. Container semantic adapters for u64/i64/DateTime were not built; the generator rejected those inputs. Regex admission was a stand-in. No runtime throughput was measured. One-minute load ranged 24–641: wall-clock build times are not comparative evidence, and sub-one-CPU-second incremental differences are noise. Cold CPU dependency differences are directional, not quiet-host build guarantees. R's chrono and tag-last fallback are superseded prototype findings, not the selected final wire contract.
